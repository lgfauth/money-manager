# Tarefas 004 — Remoção completa das notificações push

**Definição:** `specs/definition/004.definition.remocao-notificacoes-push.md`

Ordem pensada de fora para dentro, para que o sistema compile e funcione ao fim de cada
tarefa:

1. o **Web** deixa de usar o push (a API ainda tem as rotas, mas ninguém as chama);
2. o **Worker** e o **Backoffice** deixam de enviar push e perdem o lembrete diário — é
   pré-requisito da Tarefa 3, porque o Worker usa `IPushService` na importação de fatura
   e nas recorrências;
3. a **API e as camadas compartilhadas** (Application, Domain, Infrastructure) removem o
   que sobrou: rotas, serviço, entidade, repositório, configuração, pacote, testes e docs,
   com a busca final dos termos.

Nada é recriado como substituto: os avisos ficam só dentro da aplicação (indicador do
header e toasts da importação de fatura, que não mudam).

Validação comum a todas as tarefas (checklist do `AGENTS.md`): `dotnet build
MoneyManager.sln` e `dotnet test MoneyManager.sln`; em `src/Frontends/MoneyManager.Web`,
`npx tsc --noEmit -p .`, `npx eslint <arquivos alterados>` e `npx next build`; no
Backoffice, `npx tsc --noEmit -p .` e `npx eslint` se ele for alterado. Cada teste
removido tem a explicação registrada na tarefa.

Changelog (`public/changelog.md`): conforme a decisão da definição — se os itens de
notificações no navegador ainda estiverem na versão do topo com a data do dia, removê-los
(voltando a versão para patch se não sobrar funcionalidade nova); senão, nova versão com
item explicando que as notificações do navegador e os lembretes saíram. Só a Tarefa 1
tem efeito visível ao usuário; as Tarefas 2 e 3 só entram no changelog se o lembrete
diário ou o aviso de recorrentes precisarem ser mencionados (registrar a decisão).
